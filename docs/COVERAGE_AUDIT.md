# 游戏内容覆盖自检（0.3，2026-10-27）

本次先以用户列出的 13 类玩法检查“能发现选项、能提交动作、能处理后续选择”，再对照本机 Base、Rise and Fall、Gathering Storm 的操作数据及原版 UI 请求。覆盖表描述已实现的固定接口；不等同于已在真实游戏逐项验收。

## 对照方法与发现

读取以下安装源目录中的 `UnitOperations`、`UnitCommands` 表和更新条目：

- `Base/Assets/Gameplay/Data`
- `DLC/Expansion1/Data`
- `DLC/Expansion2/Data`

本机目录中共有 **55 个 `VisibleInUI=true` 的单位 Operation、26 个 `VisibleInUI=true` 的单位 Command**。这些项现在均有经过逐项映射的固定入口（包括已有移动、建城、改良等入口）。没有把任意枚举或运行时整表直接开放给 AI。`EXECUTE_SCRIPT` 和隐藏的调试/内部操作不在允许集合。

另对照 `Base/Assets/UI` 和两个资料片 UI 中实际使用的 `PlayerOperations`、`CityOperationTypes`、`CityCommandTypes`。原始按钮表并非全部玩法：普通右键移动中的 `SWAP_UNITS` 就是 `VisibleInUI=false` 的正常操作，因此还检查了 `Civ6Common.lua`、`WorldInput.lua` 的显式调用。

`tests/test_operation_coverage.py` 可在安装目录存在时重跑 XML 映射检查，并对注册表中所有动作、查询及每个顶层枚举分支生成 Lua、验证输入结构并编译。它能发现漏映射、输入字段不匹配及 Lua 语法错误；引擎语义、真实 UI 时序仍由功能测试和实机验收验证。外部 CI 没有游戏安装目录时只跳过 XML 对照，语法和结构测试仍执行。

## 用户清单以外发现并补充的内容

1. **先知创教、使徒福音传播的前置单位能力。** 招募伟人或配置宗教并不触发这些单位操作；现在有独立 `activate_prophet`、`evangelize_belief` 指令。
2. **睡眠、警戒、休整、跳过单位、取消命令、停止自动探索。** 不只是移动与驻扎。
3. **单位护送/解除编队、相邻单位换位、赠送、解散。** 换位仅涉及两个自有单位。
4. **空运、伞降、海岸突袭、优先攻击、巨型死亡机器人跳跃。** 单独的固定目标参数入口。
5. **核装置/热核装置与城市地块发射井。** 单位和城市发射请求分别核验自有发射源。
6. **军事工程师邻格隧道、修复路线、清核污染、建设加速。** 使用当前单位能力与普通操作检查。
7. **城市生产队列、直接生产/购买军团与集团军、城市间地块交换。** 不只是选择下一项普通生产。
8. **只能购买的宗教建筑遭掠夺后的生产修复，以及既有奇观的修复。** 原来的 `MustPurchase`/重新选址限制会错误挡住这些操作，已修正。
9. **保留现政体、暂存总督头衔、忠诚度归附城市接受/拒绝。** 均使用正常 UI 的当前待处理条件。
10. **间谍逃跑路线、征服城市保留/夷平/解放、文物来源选择。** 不将这些必选决策当普通通知关闭。
11. **当前外交会话响应、联合/第三方战争条款、议会可选提案已查看、紧急事件的参加/拒绝。** 不遗漏回合中途外交或议会阻塞。
12. **城市/单位命名及侦察兵抚摸狗。** 属于普通 UI 的可选操作，受能力及自身实体检查。

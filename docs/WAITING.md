# 等待公开观察变化

在普通观察或一次 `act` 后，可调用 `wait_for_change(timeout_ms=3000)`。预算必须是 1 至 10000 毫秒的整数，包括获取服务锁、读取和轮询间隔。读取中断沿用原传输层的连接清理，最多可能额外等待 1 秒；这不是硬实时的墙钟保证。工具支持 MCP／异步任务取消。

工具每 250 毫秒重做本服务上一次成功返回的同一种只读查询，保留相同参数，包括地图范围和 `inspect_game` 类别。所有读取继续经过正常 Lua 权限门槛、Python 公开字段投影和已知弹窗采集。比较基线保存固定查询描述、会话身份、公开结果哈希，以及用于变化摘要的本方字段和少量公共 UI 元数据；不保存原始状态、地图内容或外国实体缓存。

临近截止时间时，参考最近三次完整读取的最大耗时并留出余量；预算不足就等待剩余时间并返回本次最后完整观察，避免频繁开启随即被截断的末轮读取。突然变慢的实际读取仍受原硬截止约束，不掩盖中断。

返回原观察的字段，并增加：

- `wait.reason`：`observation_changed`、`ui_changed`、`turn_changed`、`timeout`、`session_changed`、`connection_changed`、`unavailable` 或 `no_baseline`。
- `wait.changed`：是否观察到了本次可比较的变化。
- `wait.elapsed_ms`：实际经过的时间，包含有界取消清理。
- `wait.read_incomplete=true`：超时发生在读取过程中。不会返回这次未完成读取的部分状态；若本次等待中已有完整观察，可以保留其公开内容，但移除令牌。
- `wait.changes`：仅在同查询、同会话／玩家／连接且读取完整时提供的有界摘要，含 `from_turn`、`to_turn` 和最多 64 个 `events`。比较本方经济、研究／市政选择、单位位置／伤害／移动力、城市人口／生产，以及公共 UI 状态、阻塞名和当前弹窗 ID；地图、外交实体和选项列表只保留原哈希比较，不存其详情作差。摘要可以为空，即便正文或其他未纳入摘要的公开字段让 `wait.changed=true`。

变化摘要只陈述观察差异。`field_changed` 的 `before_known`／`after_known` 区分可选字段缺失与真实数值；`no_longer_observed`／`now_observed` 的原因固定为 `unknown`，不能据此认定单位阵亡、新城建立或生产／研究完成。世界读取失败后的 UI 恢复不会被解释为全部单位或城市消失。`truncated=true` 表示事件超过上限。不要将这些事件当作游戏原生事件日志。

开始等待即废弃旧动作令牌。只有同一会话、玩家、连接代次内已完成的新观察，才可能返回新的动作令牌；正常换回合仍允许。会话／玩家切换、连接变化或读中断会清除能力，需另取普通观察。服务锁覆盖等待过程，其他请求不能利用轮询间隙提交旧动作。尚未取得服务锁时的超时／取消不会破坏正在执行的其他观察。

随机变化的 `observation_token` 和弹窗按钮 `action.revision` 不参与内容比较，但返回的弹窗动作保留最新 revision。按钮文字、启用状态、可用动作和已知界面正文仍参与比较。相同公开文字但内部回调换代不视为可从内容检测到的变化，执行安全仍由最新 revision 复查保证。

该工具从不提交或重放动作。观察变化不证明上一动作完成；超时也不证明动作失败，可能只是当前查询范围没有覆盖其后果。例如，上次只查研究选项，等待该查询可能看不到单位移动，应改为正常读取自有单位／目标区域。隐藏字段变化不会触发等待结果。

普通观察还提供 `ui.next_steps`，把当前阻塞映射到固定只读查询；已有弹窗提示使用本次实际提供的按钮，未知阻塞回到 `get_pending_decisions`。这是处理入口提示，不是自动决策或新增动作授权。普通观察和等待中的重读也会检测本方终局，终局结果不授予令牌；详见 [参考项目交互对照](REFERENCE_PARITY_INTERACTION.md)。

## 当前界面活动提示

正常生产观察的 `ui.engine_activity` 提供固定值 `busy`、`idle` 或 `unknown`。它只采样原版 UI 的 `IsGameCoreBusy()` 与 `IsProcessingMessages()`：任一个严格返回 `true` 为 `busy`，两者严格返回 `false` 才为 `idle`，其余情况为 `unknown`。接口缺失、异常或非布尔返回不会被当成空闲。多上下文观察中，只要某次已完成采样为 `busy`，本次提示就保留 `busy`；全部采样为 `idle` 才返回 `idle`。

该提示不改变 `ui.status`、回合权限、弹窗按钮或动作令牌，不会自动重试动作。`idle` 仅表示采样时两个 UI 信号均为空闲，不保证此前请求已经开始或完成，也不保证所有动画结束；仍应读取相关单位、地块或其他公开结果确认后效。`wait_for_change` 沿用既有公开 UI 比较，活动提示发生变化会返回 `ui_changed`，不会将其解释成操作成功。

源码依据是本机原版 `Base/Assets/UI/ActionPanel.lua:152,541` 的消息处理检查，以及 `WorldInput.lua:884`、`Panels/UnitPanel.lua:3892` 的核心忙碌检查。提示不读取队列内容、处理对象、隐藏单位或任务详情。原有 `IsProcessingMessages` 回合授权门仍保留；该必需接口在授权读取处失效时，整条普通观察仍可能按原规则不可用，而不是因新增提示降级为可执行。

这项增量的模拟回归与实机采样分别验收；`busy`／`idle` 的真实切换仍需在后续对局自然验证。

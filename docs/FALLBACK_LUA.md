# 备用 Lua 接口

**0.4.2 已实现并通过离线验证。** 用户已于 2026-10-27 明确接受任意 Lua 无法自动强制过滤隐藏信息的限制，并要求按下述备用用途继续实现。重新加载 MCP 后，以运行中的 `get_rules` 和工具列表确认可用性；尚未在当前对局中实测。验证范围见 [测试记录](FALLBACK_VALIDATION_2026-10-27.md)。

`run_lua` 是备用接口：**只有游戏中遇到当前已提供的常规接口无法解决的问题时才可以使用。** 平时继续通过状态查询、选项查询、`get_pending_decisions` 和 `act` 进行游戏。例如，常规接口无法读取某个实际显示的未知弹窗、没有对应按钮操作，或者已提供的正常操作因接口兼容问题失效时，才考虑这个入口。

这项功能按用户的明确要求引入，参考上游 `run_lua` 的用途，并保留本项目的一次提交、不自动重试和状态失效处理。它不是截图识别，也不会自动发现并修复所有未知游戏界面。调用方需要根据实际问题编写短小的 Lua 代码，先读取公开状态，再使用原版合法操作或当前可见按钮的正常回调。常规接口失败不会自动触发备用执行。

## 调用约定

```text
run_lua(
    code=<待执行的短 Lua 代码>,
    reason=<当前游戏问题，以及常规接口为什么无法解决>,
    attempted_tools=[<已尝试但不足以解决问题的常规工具名>],
    context="InGame"
)
```

`code`、`reason` 和 `attempted_tools` 必填。`reason` 必须非空，最多 2000 字符，说明真实游戏问题和常规接口不足之处。`attempted_tools` 必须有至少一个实际尝试过的游戏常规工具名，不能重复；可填 `get_game_status`、`get_player_state`、`get_diplomacy`、`observe_area`、`list_options`、`inspect_game`、`get_pending_decisions`、`wait_for_change`、`act`。静态资料查询、规则说明和备用入口自身不能充当已尝试的游戏操作。

服务会验证参数形状和工具名，但这只是调用方提供的故障说明，不能据此证明该工具确实尝试过，也不能自动证明备用脚本有必要或符合公平规则。`attempts_verified=false` 明确表示这一限制；不要编造失败记录。

`context` 默认 `InGame`，也接受 `ingame` → `InGame`、`gamecore` → `GameCore_Tuner` 别名，以及当前 FireTuner 实际发现且名称唯一的 Lua 上下文。不存在或名称有歧义的上下文不会执行。**发现上下文不等于该上下文可用**：执行包装还要求目标上下文具备必要的本地玩家身份 API，以及与前检相同的共享会话状态；缺失时拒绝。GameCore 可能无法通过这些检查，不能承诺可在其中执行。普通工具仍只使用已审计的固定上下文；GameCore 也不是公平或只读沙箱。

服务先做一次新的最小游戏身份检查：必须是进行中的单人对局、本地存活人类玩家，且观察者身份与本地玩家一致；多人、热座、自动演示、编辑器和无法可靠确认的身份状态不可使用。备用执行绑定检查时的连接代次，不因中途重连而重新执行。目标上下文在用户代码运行前再次核对模式、玩家、观察者、存活人类身份、回合、未结束状态和会话；同一连接中读档或切换玩家也不能沿用前检。

这个前置检查不要求常规观察令牌，不依赖普通弹窗扫描成功，也不要求普通活动回合已经就绪。因此，未知模态弹窗导致常规接口无法发放动作令牌时，备用入口仍可用于处理当前玩家实际面对的界面。它不授予其他玩家的操作权，也不允许绕过游戏阶段和正常操作资格。

## 公平性和电脑环境

普通接口仍通过已编写的 Lua 检查和 Python 字段投影限制可见信息。**任意 Lua 的输入、输出和副作用无法套用这些固定字段规则，`run_lua` 不是自动公平过滤器或安全沙箱。** 本地身份前置检查只确认当前玩家身份，不能证明脚本随后读取的每个对象或发出的每个请求都是合法的。

使用备用接口仍必须遵守玩家权限：

- 只读取当前玩家正常界面实际可知的信息，包括正常菜单实际提供的选项。未知弹窗只检查当前显示的正文、按钮和启用状态，不读取隐藏子树或待显示事件队列。
- 不读取未探索或迷雾中的实时世界详情、未解锁战略资源、未被探测的单位、未遇见文明身份、隐藏议程、随机种子或未来奖励。
- 使用当前玩家正常合法的游戏请求和原版界面回调；不得通过作弊 setter 直接修改资源、科技、行动点、其他玩家状态、视野或胜负，不强制结束回合，不粗暴隐藏弹窗以跳过必选决策。
- 不读写电脑文件、存档或日志，不执行系统命令，不联网，不修改系统或游戏安装配置，不结束进程。不能把任意 Lua 能访问到的能力视为用户授权。
- 只执行短小、有界的代码；不使用无限循环、无限递归、大范围世界遍历或忙等。

这些是调用方必须遵守的使用约束，不是已由任意字符串黑名单或运行时沙箱证明的技术保证。需要强制隔离的公平比赛应只向玩家代理暴露常规工具，移除备用执行能力，并阻止代理直接连接 FireTuner 或其他高权限入口。日常联调开放备用工具时，调用方必须能够遵守以上约束。

## 执行与输出

代码作为 Lua 字符串传入独立的编译包装，优先使用游戏提供的 `loadstring`，兼容环境回退到 Lua 5.3 的文本模式 `load`。包装保留目标上下文的正常全局 API；文本模式和局部变量不构成沙箱。

脚本中的普通 `print(...)` 使用本次调用的局部收集器，不替换上下文全局 `print`。只收集此次脚本显式打印的内容和支持的第一个标量返回值，不自动遍历返回的表或 userdata。需要查看公开对象时，显式选择必要的公开标量字段逐个打印；不要打印整个世界对象。通过 `_G.print` 或其他函数内部的全局日志输出不会作为这次脚本的打印结果收集。

代码按 UTF-8 编码上限为 32 KiB，拒绝空代码、NUL 和非文本控制字符（制表符、换行和回车除外）。一次 `print` 最多接受 64 个参数，转换并以制表符连接后的文本最多 4096 字节；过长时省略该次打印并标记 `truncated=true`。打印结果按换行拆分，最多 128 行，累计文本最多 64 KiB；超出容量的行不再返回，不在 UTF-8 字符中间截断。这个上限约束响应量，不能限制脚本自己创建的大对象或运行时间。

只返回第一个标量返回值；字符串上限为 4096 字节。表、userdata、函数、线程及不支持的数值不会被遍历或自动序列化，而是标注类型及省略状态。语法和运行错误的文字也限制为 4096 字节，过长时返回省略说明。备用诊断与普通工具隐藏原始引擎错误的策略不同，同样可能含脚本访问的数据，所以必须先限制脚本读取范围。传输仍只接收当前请求标记及目标上下文的响应，不附送其他全局日志。

参数通过校验后，正常返回的响应附带 `receipt`：请求 ID、上下文、代码 SHA-256、原因、已尝试工具以及 `retention=response_only`。这是本次调用的回执，不是持久审计日志；服务不向磁盘写入回执或原始代码，也不新增历史查询工具。参数不合法时不执行脚本；取消调用可能没有可返回的回执。

## 结果确认与恢复

一次调用最多执行一次脚本，超时、断线、取消或错误都不自动重试。Lua 运行错误可能发生在前面的游戏请求已经产生效果之后；超时或连接错误同样不能证明没有执行。不要把这些结果当作可以直接重发的拒绝。

备用调用后，原有普通动作令牌、等待观察基线、会话历史和预览授权会失效，无论脚本成功、失败还是取消。重新调用常规观察工具确认实际游戏状态，再获取新的动作令牌；`status=completed` 只表示 Lua 调用返回，`operation_completion=not_asserted` 表示未确认游戏异步请求完成。`script_executed=null` 或 `fallback_outcome_unknown` 时不能据此认定脚本未运行。如果常规观察仍不可用，下一次备用诊断应先查明公开状态，避免重复之前可能已执行的操作。

**客户端超时只会停止等待并断开连接，不能保证终止游戏引擎中已经运行的 Lua。** 本服务没有引擎级 CPU 中断保证。若无法安全确认和解决问题，应保留当前游戏等待用户，不杀游戏进程，也不通过系统改动强行恢复。

重复遇到的缺口应补成有固定参数、玩家权限检查和结果投影的常规接口。备用入口用于解除实际遇到的接口缺口，不取代常规功能开发。

# 0.4.2 备用 Lua 验证记录

用户在本轮明确接受技术限制后，按正常审批路径完成 `run_lua` 实现。该功能不是自动公平过滤器或沙箱，只允许处理已提供常规接口无法解决的实际游戏问题。使用规则见 [备用 Lua 接口](FALLBACK_LUA.md)，知情确认见 P10。

本轮只做离线验证，未连接或操作当前对局，没有修改全局环境、游戏设置或存档，没有删除文件。GameCore 等上下文仍要求目标玩家身份 API 与共享会话可验证；发现上下文不代表能够在其中执行。

验证结果：

- 122 项执行器测试通过：使用真实 Lupa Lua 解释器运行生成代码，覆盖两种加载分支、UTF-8、源码大小与字符串包装、隐藏/未知 UI 不阻塞最小身份预检、非活动回合、多人/死亡/观察者拒绝、同连接读档与玩家/回合变化拒绝，以及返回对象不遍历。
- 服务、传输与真实 MCP stdio 定向测试：42 项通过、31 项子测试通过。覆盖必填参数、备用说明、回执、取消与连接关闭异常、各阶段旧状态失效、未知结果和不自动重放。使用模拟引擎和 loopback 测试服务，不连接真实 FireTuner。
- 完整离线回归：**3439 passed, 1 skipped, 50 subtests passed，30.43 秒**。跳过项是手册测试所需的 Windows 符号链接创建权限，不为测试更改系统权限。
- `uv lock --check --offline` 通过。

关键结果语义：编译失败表示用户代码未运行；运行失败可能已有副作用；超时/断线/无效响应返回未知执行结果。Lua 返回成功只表示脚本结束，不证明异步游戏操作完成。无论成功、失败或取消，普通令牌、等待基线、会话历史和预览授权失效，后续先重新观察。

执行器采用直接编译 `local print = ...;` 加用户文本的方式，避免函数工厂包装允许代码提前闭合后在“编译”阶段产生副作用的问题。只捕获脚本的局部 `print`，不替换全局输出，不自动递归序列化返回表。

当前 MCP 共 13 个工具；51 个常规分类查询和 84 种常规动作保持原有权限检查。新增备用接口的非结构化输出不适用这些固定字段投影保证。实际游戏 Lua 环境与具体未知弹窗的恢复仍待用户新对局验证，不能把离线通过视为所有实机故障已解决。
